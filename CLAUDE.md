# CLAUDE.md

이 저장소의 진입점이다. **규칙의 단일 출처는 [AGENTS.md](AGENTS.md)다** — 여기서 반복하지 않는다. 먼저 `AGENTS.md`를 전부 읽고, 작업 유형에 맞는 `.claude/skills/*/SKILL.md`를 함께 따른다.

| 작업               | 스킬                                                  |
| ------------------ | ----------------------------------------------------- |
| 화면·컴포넌트 구현 | `component` (+ SEED 사용법·설치·진단은 `seed-design`) |
| 코드 점검·리팩터   | `code-quality`                                        |
| 테스트 작성        | `test-strategy`                                       |
| 커밋·PR            | `pr-workflow` → `self-review` → `follow-review`       |
| 새 스킬 추가       | `skill-creator`                                       |

SEED 컴포넌트 API·토큰은 기억으로 쓰지 않는다. `seed-docs` MCP(`.mcp.json`)나 `https://seed-design.io/react/llms.txt`에서 확인한다.

## 완료 기준

- [ ] `pnpm check-types`, `pnpm lint`, `pnpm test`가 0 에러로 통과한다.
- [ ] 새 파일이 `AGENTS.md` §1의 레이어 표와 맞는 위치에 있고, 슬라이스 밖에서는 `index.ts`로만 import한다.
- [ ] `src/` 아래 `*.css.ts`에 hex 색상과 px 간격이 없다(`entities/frame` 제외).
- [ ] export한 함수·훅·컴포넌트마다 영어 JSDoc이 있고, UI 문구·주석·테스트 설명에 한글이 없다.
- [ ] UI를 건드렸으면 `pnpm dev`로 띄워 사진을 열고 저장까지 직접 확인했다. 확인하지 못했으면 그렇다고 보고한다.
- [ ] 로그인 화면·마이그레이션을 건드렸으면 `docs/verification.md`의 방법으로 확인했다. 마이그레이션이 든 PR은 사용자 확인을 받고 머지한다.

## 불확실할 때

1. **`AGENTS.md`와 코드가 다르다** → 관련 파일 2~3곳을 더 읽고 실제 패턴을 따른 뒤, 불일치를 한 줄로 보고한다. 어느 한쪽을 임의로 "고치지" 않는다.
2. **기획상 미확정인 값이 필요하다**(레시피 수치, C1~C7 배치, 필름 정확한 제품명, 워터마크 표기) → 지어내지 않고 사용자에게 묻거나 비워 둘 수 있게 만든다.
3. **SEED에 맞는 컴포넌트가 있는지 모르겠다** → `seed-design` 스킬 절차대로 문서 인덱스를 먼저 읽는다. 없다고 확인된 뒤에만 직접 만든다.
4. **작업 범위가 커진다** → 원래 요청만 끝내고 나머지는 "다음 작업 제안"으로 보고한다.
