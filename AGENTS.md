# AGENTS.md

이 저장소에서 일하는 모든 에이전트의 **단일 출처**다. 아키텍처, 스타일, 도메인 규칙, 테스트, 워크플로우, 접근성 기준이 여기 있다. 스킬(`.claude/skills/`)은 이 문서를 참조만 하고 규칙을 복제하지 않는다. 결정의 배경은 [docs/architecture.md](docs/architecture.md)에 있다.

STOCKROLL은 Lightroom 보정 이후 단계를 맡는 **개인용 사진 프레임 PWA**다. Vite + React SPA, SEED Design, vanilla-extract, Supabase, Vercel.

## 1. 아키텍처: Feature-Sliced Design

도메인과 UX 단위로 묶는다. 기술 종류(components/hooks/utils)로 묶지 않는다.

| 레이어          | 역할                                     | 지금 있는 것                                                                                                                                                                                                                                   |
| --------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/app/`      | 진입점·프로바이더·전역 스타일. 로직 없음 | `main.tsx`, `App.tsx`, `global.css.ts`, `theme.css.ts`(SEED 색 덮어쓰기), `seed-overrides.css.ts`(SEED 모양 덮어쓰기)                                                                                                                          |
| `src/pages/`    | 화면 조립                                | `landing/`(`/`), `editor/`(`/frame`), `library/`(장비·필름 `/library/*`, 레시피 `/recipes/*`, 레시피 카드 `/recipes/:id/card`, 스트립 `/recipes/strips/*`, 공용 목록 `LibraryList`), `legal/`                                                  |
| `src/widgets/`  | 여러 화면이 공유하는 독립 UI 블록        | `app-bar/`, `site-footer/`, `page-shell/`                                                                                                                                                                                                      |
| `src/features/` | 사용자 상호작용·상태 단위                | `frame-photo/`(사진 큐·캡션·내보내기), `auth/`(`SignInGate`, 세션)                                                                                                                                                                             |
| `src/entities/` | 도메인 모델과 순수 계산                  | `frame/`, `photo/`(EXIF), `gear/`(카메라·렌즈·필름), `recipe/`, `mark/`(내 텍스트·이미지 — 프레임과 레시피 카드 공용)                                                                                                                          |
| `src/shared/`   | 도메인을 모르는 범용 코드                | `api/`(Supabase, `createCollection`), `lib/`(`pick-filter`, `search`, `use-collection-page`, `record-field`, `resize-image`, `save-file`, `canvas-fonts`), `ui/`(아래 공통 부품), `config/`(`palette`, `responsive`, `messages`, `typography`) |
| `seed-design/`  | SEED CLI가 내려받는 스니펫               | `ui/*` — **직접 고치지 않는다**                                                                                                                                                                                                                |

- **의존 방향**: `app → pages → widgets → features → entities → shared`. 역방향 import 금지.
- **공개 API**: 다른 슬라이스는 `index.ts`로만 import한다(`@/entities/frame`). 내부 파일을 직접 뚫지 않는다.
- **슬라이스 안**: `ui/`(컴포넌트·`*.css.ts`), `model/`(상태·훅·타입), `lib/`(순수 함수).
- **그룹핑**: 같은 상태·생명주기를 공유하면 한 슬라이스다. 편집 상태를 공유하는 캡션 수정·내보내기를 `features/edit-caption`, `features/export-jpeg`로 쪼개지 않고 `features/frame-photo`에 둔다.
- **계산은 React 밖에 둔다**: 레이아웃·포맷처럼 입력→출력이 정해지는 로직은 `entities/*/model|lib`의 순수 함수로 두고, 훅은 그걸 조립만 한다. Node 테스트로 검증할 수 있게 하기 위해서다.

## 2. 프론트엔드·스타일 규칙

### 개발 표준

- 모든 함수는 `const` 화살표 함수.
- **코드 안의 언어는 영어다**: UI 문구, 주석, JSDoc, 테스트 설명, README, `<html lang="en">`. 커밋 메시지와 PR 본문만 한국어로 쓴다. 예외는 붙여넣기가 알아듣는 한국어 낱말 하나뿐이다 — `entities/recipe/model/paste-korean.ts`(과 그 테스트의 입력)에만 두고, 화면에 보이는 글자로는 쓰지 않는다.
- export하는 함수·훅·컴포넌트에 **영어 JSDoc**(파라미터·반환값 포함).
- import는 `@/...`, `seed-design/...` alias. 같은 슬라이스 안에서만 상대 경로.
- 불필요한 `div` 래퍼 금지, 시맨틱 요소 우선. 죽은 코드·임시 `console.log` 금지.
- 같은 패턴이 3번 나오기 전에는 공통화하지 않는다.

### 스타일 — SEED 먼저, 나머지는 vanilla-extract

1. **SEED 컴포넌트로 되면 SEED로 끝낸다.** 필요한 컴포넌트는 `pnpm dlx @seed-design/cli@latest add ui:{id}`로 받고 `seed-design/ui/*`에서 import한다. 버튼·입력·선택 컨트롤을 직접 만들지 않는다.
2. **SEED가 덮지 못하는 레이아웃·커스텀 UI만** 컴포넌트 옆 `{Component}.css.ts`(vanilla-extract)에 쓴다.
3. **브랜드 컬러**(무드보드를 화면용으로 다듬은 값): 빨강 `#8E211E`(키) · 초록 `#1F4E3D`(세컨드) · 갈색 `#4B3427`(서드) · 차콜 `#141414` · 크림 `#F4EFE3`(배경) · 아이보리 `#FAF7EF`(카드). 원본 값은 `src/shared/config/palette.ts` 한 곳에만 두고(`BRAND`, 파생값은 `SHADE`), `src/app/theme.css.ts`가 SEED 시맨틱 변수를 이 팔레트로 덮어쓴다.
4. **색·간격·radius·글자 크기는 `@seed-design/css/vars`의 `vars` 토큰만.** hex·px 하드코딩 금지. 그리드 트랙 폭 같은 레이아웃 치수는 `rem`/`dvh`로 쓴다. 선 두께(`1px`·`2px` 테두리와 밑줄)만 px로 쓴다.
5. **모든 화면은 폰 폭(약 360px)까지 반응형이다.** 분기는 `src/shared/config/responsive.ts`의 `COMPACT_MEDIA_QUERY`(≤760px: 헤더 메뉴가 햄버거 + 사이드 드로어로, 편집기는 세로로 쌓임)와 `NARROW_MEDIA_QUERY`(≤560px: 나란한 줄이 쌓임)만 쓴다. 글자는 자르지 말고 줄바꿈한다(`nowrap`은 메타데이터 값처럼 말줄임이 의도일 때만). 페이지에 가로 스크롤이 생기면 버그다(레시피 스트립처럼 한 줄짜리 띠가 자기 안에서 옆으로 넘기는 것은 예외다).
6. **폰의 편집기는 문서가 스크롤한다.** 화면 높이에 고정한 틀(`100dvh` + 안쪽 스크롤)은 iOS 브라우저 하단 바 위에서 끝나 그 뒤에 빈 띠를 남긴다. 좁은 폭에서는 페이지가 스크롤하고 미리보기만 `sticky`로 붙인다. 붙은 요소의 높이는 `svh`(`dvh`는 바가 접힐 때 튄다), 가장자리 여백은 `env(safe-area-inset-*)`. 설정까지 스크롤하면 미리보기를 `40svh`로 줄이고 맨 위에서 되돌린다(`shared/ui/use-folded-stage`). 입력칸에 포커스가 있는 동안과 높이 520px 이하에서는 고정을 푼다 — 화면 키보드는 CSS 뷰포트 단위를 바꾸지 않아서 붙은 미리보기가 입력칸을 덮는다.
7. **SEED 컴포넌트의 모양을 고칠 때는 `src/app/seed-overrides.css.ts` 한 곳에서, `html` 접두 선택자로 덮는다.** 스니펫(`seed-design/ui/*`)은 고치지 않는다. 크기는 덮어쓰기 전에 SEED가 가진 변형부터 쓴다(Select·TextField는 `size="medium"`이 있다).
8. 다른 스타일 도구(Tailwind, CSS Modules, Emotion 등)를 들이지 않는다.
9. 컴포넌트는 `className` 외의 레이아웃 prop(margin, gap)을 받지 않는다.

> **UI는 고급 아날로그 카메라 브랜드처럼 보여야 한다 — 필름 패키지, 보관용 라벨, 제품 카탈로그. 다크모드 SaaS 대시보드도, 레트로 장난감(두꺼운 테두리 + 오프셋 그림자 + 전부 모노스페이스)도 틀린 것이다.** 테마는 하나뿐이다(SEED `light-only` 고정, 시스템 라이트/다크와 무관): 따뜻한 오프화이트 배경 + 차콜 잉크, 빨강(키) → 초록(세컨드, 아껴 씀) → 갈색(서드, 거의 안 씀). 형태 규칙: 테두리는 1px, 카드·버튼·탭에 그림자 없음(사진 미리보기의 부드러운 그림자 하나만 예외), 강조는 선·정렬·여백으로 한다. 서체는 역할을 나눈다 — 워드마크·큰 제목만 Anton, 메뉴·라벨·메타데이터만 대문자 타자기체(`labelText`), **본문은 기본 산세리프**. 버튼은 `shared/ui/Button`(납작한 라벨형, 색 면 위에서는 `inverse`), 카드는 `shared/ui/label.css.ts`의 `card`, 목록 위 요약은 `MetaList` 두 줄(REGISTERED + 하나)을 쓴다. 화면 틀은 `widgets/page-shell`이다. 예외는 그림을 만드는 두 화면(프레임 편집기, 레시피 카드)이고, 둘은 `shared/ui/workbench.css`의 같은 틀을 쓴다 — 왼쪽 미리보기, 오른쪽 설정 패널, 폰에서는 미리보기가 위에 붙는다. **출력물의 배경색(`FrameStyle.background`)은 UI 테마와 별개**다.

> **화면은 공통 부품으로 조립한다. 같은 모양을 페이지마다 다시 쓰지 않는다.** 틀은 `widgets/page-shell`, 제목은 `shared/ui/PageHeader`, 내용 상자는 `Panel`, 비어 있음·로딩·없음 안내는 `EmptyState`, 요약 줄은 `MetaList`, 버튼은 `Button`, 오류는 `ErrorText`(채운 박스 금지), 설정 한 칸은 `Control`(색은 `SwatchRow`, 내 이미지 고르기는 `ImagePick`), 선택은 `PickField`(폼은 기본 크기, 촘촘한 패널·필터는 `size="medium"`, 필터 줄은 `hideLabel`), 폼은 `RecordForm`, 켜고 끄는 버튼은 `Button`의 `pressed`. 한 기록에 할 수 있는 일이 여럿이면 `ActionMenu`(버튼 하나 + 설명이 붙은 항목 목록). **장비·필름·레시피 목록은 `pages/library/ui/LibraryList`의 `ListFilters`(검색칸 + 드롭다운 + `★ Favorites`)와 `ItemList`(이름·사실 한 줄, 오른쪽 별표), 긴 목록을 잇는 `ListMore`로만 만든다** — 새 목록도 같은 모양이어야 한다. 스트립은 필터가 없어 `ListSearch`만 쓴다. 예외는 레시피를 예시 사진으로 보는 `RecipeGallery` 하나다(레시피 목록의 `Photos` 보기, 스트립의 레시피 고르기) — 같은 필터 아래에서 줄 대신 사진 칸으로 바꿔 보여 줄 뿐이고, 새 사진 격자를 따로 만들지 않는다. 좁히는 일은 DB가 하고(§3-36), 화면은 고른 값을 `shared/lib/pick-filter`의 `activePicks`로, 검색어를 `shared/lib/search`로 넘길 뿐이다. 메모는 `NoteText`로 줄바꿈까지 그대로 보여 준다(`MetaList` 줄에 넣으면 한 줄로 잘린다). 글자 목소리는 `label.css.ts`의 `displayText`·`labelText`·`labelTitle` 셋뿐이고 서체 상수를 직접 쓰지 않는다. 반복되는 문구는 `shared/config/messages.ts`, 미디어 쿼리는 `responsive.ts`에 둔다. 새 화면에서 이 중 맞는 게 없을 때만 새로 만들고, 두 번째로 필요해지면 `shared/ui`로 올린다.

> **캔버스는 CSS 토큰을 못 쓴다.** `entities/frame`이 그리는 출력물의 색·치수는 1080 폭 기준 상수와 `FrameStyle`로 관리한다. 글자색은 배경색에서 계산한다(`inkFor`). 이 영역의 숫자는 토큰 규칙의 예외다.

## 4. 테스트

- **Vitest, Node 환경이 기본**이다. 순수 로직(`entities/*/model|lib`, `shared/lib`)을 co-located `*.test.ts`로 검증한다.
- 캔버스·`createImageBitmap`·파일 API 스텁이 필요해지면 스텁을 늘리기 전에 계산을 순수 함수로 뽑는다.
- 테스트 설명은 **계약** 형식으로 영어로 쓴다: "when [condition], it must [expected result]". `"works"`, `"렌더된다"` 같은 라벨 금지.
- 캔버스 렌더링·파일 저장·PWA 설치는 실제 브라우저에서 사진을 열어 저장까지 확인한다. 자동 테스트만으로 완료 처리하지 않는다.
- 로그인해야 보이는 화면과 마이그레이션은 [docs/verification.md](docs/verification.md)의 방법으로 확인한다(가짜 세션 + 가짜 응답, 일회용 Postgres). **확인하지 못한 것은 못 했다고 적는다** — 실기기(iOS Safari, 설치한 PWA)는 자동화로 볼 수 없다.
- **테스트용 사진을 커밋하지 않는다.** `.tmp/`, `samples/`는 gitignore다.
- 날짜가 걸린 테스트는 `TZ=UTC pnpm test`로 한 번 더 돌린다(로컬 Asia/Seoul, CI UTC).

## 5. 워크플로우

- 커밋은 의미 있는 논리 단위로. 타입은 `feat:` `fix:` `refactor:` `style:` `docs:` `chore:` `remove:` `test:` `perf:` `ci:` — **gitmoji를 붙이지 않는다**(`.husky/commit-msg`가 검사). 본문은 한국어로, **무엇보다 왜**를 쓴다.
- PR 본문 구조: `목적 → 설계 → Changes → 리뷰 포인트 → Test plan → 후속`. Test plan에는 실제 실행한 명령과 결과만.
- `gh`는 `env -u GITHUB_TOKEN gh`로 실행한다(개인 계정 `pcwadarong`).
- 스키마 변경은 `supabase/migrations/`에 새 파일로. 적용된 마이그레이션을 고치지 않는다.
- **`main`에 머지하면 Supabase가 마이그레이션을 실제 프로젝트에 바로 적용한다**(GitHub 연동, `Supabase Preview` 체크). 그래서 마이그레이션이 든 PR은 사용자 확인 없이 머지하지 않고, 기존 행을 바꾸는 `update`는 되돌릴 수 없는 값을 덮어쓰지 않는지 본다. **SQL Editor로 스키마를 직접 바꾸지 않는다** — 적용 기록이 남지 않아 다음 배포가 같은 문을 다시 돌리다 실패한다.
- AI 리뷰(Codex, CodeRabbit)는 ✅ 반영 / 🤔 사용자 확인 / ❌ 이유를 달고 넘김으로 나눈다(`follow-review` 스킬). CodeRabbit 무료 한도에 걸리면 한도가 풀린 뒤 PR에 `@coderabbitai review`를 남긴다.
- 커밋·푸시·PR·마이그레이션 적용·의존성 제거는 실행 전에 사용자에게 확인한다.

## 6. 접근성

- 모션(헤더 메뉴 밑줄이 왼쪽에서 그어지는 호버 등)은 `prefers-reduced-motion: reduce`에서 끈다. 호버 효과는 `:focus-visible`에도 똑같이 건다.
- 네이티브 요소·SEED 컴포넌트 우선, ARIA는 그다음.
- 모든 인터랙티브 요소는 Tab/Enter/Space로 조작 가능. 포커스 아웃라인을 지우지 않는다.
- 동적 상태 변화는 `aria-live`/`role="alert"`. 미리보기 `canvas`에는 `role="img"`와 `aria-label`.
- 캔버스에만 있고 DOM에는 없는 정보를 만들지 않는다 — 캡션 값은 입력 필드로도 읽을 수 있어야 한다.
